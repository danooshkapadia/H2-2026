# Second-Screen Session Sheet — Structure Reference

Load this when producing Artifact 2 in Step 6.

## Purpose

This is the document Danoosh has open on his second monitor (or iPad) during the live session. He glances at it, not reads it. Every element must be scannable in 2 seconds or less.

Think of it as a teleprompter for a coach. Not a script. A set of anchors that keep him on track without breaking his presence with the client.

## Design principles

- **Glanceable.** If Danoosh has to read a paragraph mid-session, the design failed. Use fragments, not sentences.
- **One page ideal, two pages max.** If it spills to a third page, cut ruthlessly. Better to have less that he actually uses than more that he ignores.
- **Visual hierarchy matters.** Headers, bold, whitespace. His eye should land on the right section without searching.
- **No internal coaching notes on this sheet.** Those belong in the facilitation guide. This sheet is pure structure and content cues.

## Structure

### Header (always present)

```
SESSION [N] — [CLIENT FIRST NAME] | [Date] | [Start Time]–[End Time]
Topic: [One-line topic]
```

### Timing rail (always present)

A single horizontal bar or table showing the session segments and approximate times:

```
CHECK-IN (15m) → CONCEPT (10m) → BUILD (35m) → CLOSE (15m)
```

Or as a simple table:

| Block | Time | Key move |
|-------|------|----------|
| Check-in | 0:00–0:15 | Homework review, energy read |
| Concept | 0:15–0:25 | [One-line concept] |
| Build | 0:25–1:00 | [What they're building] |
| Close | 1:00–1:15 | Takeaways, homework, next session |

### Homework review checklist

A simple checklist of what was assigned last session. Danoosh checks them off as the client reports:

```
□ [Homework item 1]
□ [Homework item 2]
□ [Homework item 3]
```

### The concept (3–5 bullet fragments)

Not an explanation. Just the anchor phrases Danoosh needs to stay on message:

```
CONCEPT: [Name]
• [Core idea in 5–8 words]
• Analogy: [The metaphor to use]
• Bridge: "[Why this matters for you because...]"
• Check: "[Ask: ___________?]"
```

### The build (step sequence)

Numbered steps, each one line. Enough detail to remind Danoosh what's next without having to think:

```
BUILD SEQUENCE:
1. [Action] — CLIENT DRIVES
2. [Action] — DANOOSH DEMOS
3. [Action] — CLIENT DRIVES
4. [Action] — together
5. [Action] — CLIENT DRIVES
```

Mark who drives each step (CLIENT or DANOOSH or TOGETHER). This keeps Danoosh from accidentally taking over.

### Key prompts / templates (if applicable)

If the build involves specific prompts the client will type or Danoosh will paste into Zoom chat, include them verbatim in a clearly labeled box:

```
PROMPT TO PASTE:
"[Exact prompt text ready to copy-paste into Zoom chat]"
```

Keep to 1–2 prompts max. If more are needed, put them in a separate doc and link to it.

### Homework to assign

Pre-written so Danoosh doesn't have to improvise at minute 70:

```
HOMEWORK:
1. [Item] — [one line on what/why]
2. [Item] — [one line on what/why]
3. [Stretch] — [one line, clearly marked optional]
```

### Close cues

```
CLOSE:
• "What are 3 things that stood out?"
• "Anything you want me to do differently?"
• Next session: [Date, Time]
```

### Danger zones (optional, only if relevant)

A small section at the bottom, visually distinct, for things to avoid:

```
⚠ WATCH FOR:
• [Scope creep risk: if client asks about X, redirect to Y]
• [Don't go down the Z rabbit hole, save for Session N+1]
• [Client may bring up topic — listen, don't fix]
```

## Formatting rules (for the output file)

- **Produce as a markdown file (.md)** saved to outputs. Danoosh will open it on his second screen.
- Use monospace or code blocks for prompts to paste
- Use checkbox syntax (□) for homework review items
- Use ALL CAPS for section headers on this sheet (visual hierarchy for glancing)
- Bold the client-drives vs. danoosh-drives markers
- Maximum 2 pages when rendered. Test by counting: if you have more than ~60 lines of content (excluding whitespace), you're probably over.
- No prose paragraphs. Fragments only. This is a reference sheet, not a document.
